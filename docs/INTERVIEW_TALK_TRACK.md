# Interview talk track

**Problem:** Production incidents require engineers to correlate metrics, logs, deployment history and runbooks. Generic chatbots often answer without enough evidence.

**Design:** I built OpsPilot as a tool-using investigator. The API gathers structured evidence first, ranks a root-cause hypothesis, retrieves the relevant runbook, and keeps remediation behind explicit human approval.

**Evaluation:** I created labeled failure scenarios rather than judging outputs subjectively. The benchmark measures root-cause accuracy, evidence-source coverage, investigation latency and unsafe-action rate. I only report numbers generated by the benchmark.

**Tradeoff:** I made the core deterministic so the demo is reproducible and free to run. The next step is adding an LLM planner/synthesizer while retaining deterministic tools and verification as the source of truth.

**Scale path:** In production I would replace demo telemetry with OpenTelemetry/Prometheus and log storage, persist incidents in PostgreSQL, introduce async workers/queues, enforce RBAC and policy checks, and deploy on Kubernetes with tracing and SLOs.
